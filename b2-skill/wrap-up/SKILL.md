# 收工

依次完成测试、改动审查、调试代码检查和摘要。某一步失败时，继续能够独立完成的后续检查，保留失败结果。

读取项目的 AGENTS.md、Git 状态和测试入口。用户指定任务起点或目标分支时，以此为基线；否则使用 HEAD。没有 HEAD 时，检查全部待交付文件。摘要中写明实际检查范围。

保留用户已有改动，不切换分支或改动暂存区。“收工”只启动检查，不自动修复、删除文件、commit、push、创建 PR 或发布。已有明确修复授权时，修复后重跑受影响的测试并审查最终差异。

## 1. 运行测试

从项目规则、包管理器脚本或 CI 确定命令，每次收工都运行一遍覆盖本次改动的现有测试及项目要求的检查。

记录运行目录、命令、退出状态和通过、失败数量。没有测试、缺依赖、权限拒绝或超时，如实写明原因。失败时保留关键报错，不删除用例或放宽断言。

## 2. 完整审查改动

先列出文件，再读完差异和必要的调用上下文：

- `git diff --cached --stat`、`git diff --cached --no-ext-diff`：已暂存内容。
- `git diff --stat`、`git diff --no-ext-diff`：未暂存内容。
- `git ls-files --others --exclude-standard -z`：按实际文件名读取未跟踪的待交付文件。
- 基线到 HEAD 的差异：覆盖本次任务中已提交的改动。

核对需求、错误路径、权限和兼容行为。输出截断时分段读完，图片和二进制用相应工具查看；无法查看的文件列入摘要。凭证问题只报告位置，不输出凭证值。

发现问题时写明文件位置、触发条件和影响；推测注明依据，不修改无关内容。

## 3. 检查临时调试代码

搜索本次改动和新文件中的 `console.log`、`debugger`、临时 print、本机绝对路径、跳过测试或错误处理的代码、写死的账号与返回值。

结合上下文逐条判断，区分临时调试代码、正式日志、测试数据和文档示例。搜索结果不直接作为删除依据，也要检查没有关键词的逻辑绕过和假数据。

## 4. 简短汇总

按以下四项报告：

1. **测试**：命令、结果、覆盖范围；未运行时说明原因。
2. **改动审查**：审查范围、问题位置与影响；列出无法审查的文件。
3. **调试代码**：遗留的临时代码；命中但应保留的日志或测试数据。
4. **改动摘要**：改了什么、为什么改，以及影响交付的问题。
